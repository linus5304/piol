# Growth-First Monetization Roadmap

This document defines how Piol prioritizes user growth now while preserving a clear path to revenue later.

## Summary

Piol should optimize first for:
- trusted listings
- landlord verification quality
- renter discovery speed
- messaging/visit conversion

Piol should **not** optimize first for payment conversion.

Payments and escrow remain valuable infrastructure, but they are a later-stage monetization lever after core usage is strong.

## Product Principle

Keep renter entry friction low:
- browsing should be easy
- saving and messaging should be simple
- trust should come from verification and listing quality

Keep trust friction where it matters:
- landlord verification remains the primary gate before publishing/scale

## Phase Plan

## Phase 1: Adoption (Now)

Goal: get more renters and landlords using the product regularly.

Primary product focus:
- listing quality and freshness
- verified landlord onboarding
- search/filter UX
- fast messaging and visit coordination
- trust/safety guidance

User experience policy:
- de-emphasize payments in navigation and public marketing copy
- keep payment pages/features non-primary and staged

Success signals:
- more listing views per user
- more conversations started
- better landlord response rate
- more verified landlords
- more repeat sessions

## Phase 2: Activation Monetization (Before Payments)

Goal: monetize value created for landlords without increasing renter friction.

Recommended monetization options:
- promoted listings / boosted visibility
- landlord subscription for advanced listing tools
- lead management / response tools for landlords
- verification priority or premium verification SLA

Why this phase first:
- monetizes attention and workflow value
- avoids forcing renters into payment behavior too early
- aligns with landlord-side willingness to pay for qualified leads

## Phase 3: Transaction Monetization (Later)

Goal: activate optional transaction rails once usage and trust are established.

Use existing payment infrastructure for:
- optional escrow checkout
- convenience fees on successful transactions
- premium protection features
- landlord disbursement automation

Prerequisites before promoting payments:
- stable core marketplace usage
- reliable support/incident handling
- production callback validation
- clear user trust messaging and dispute process

## Practical Execution Rules

- Do not remove payment backend capabilities; keep them maintained.
- Do not make payments the headline marketing message during adoption phase.
- Prefer growth metrics (usage, conversations, verified landlords) over payment metrics in early product prioritization.
- Revisit monetization emphasis only after adoption metrics stabilize.
